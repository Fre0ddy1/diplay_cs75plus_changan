# 72版：仪表联动与公版修复

在71维护基线2e4a57a上实现。没有合并或改写master；没有安装或改动车机。

## 仪表开关

设置→仪表盘增加“连接手机时拉起原车高德”，默认关闭，与原有“自动飞屏”共用一个定制状态，任意一处开关都同步影响另一处。首次升级也默认关闭，旧版隐式开启的auto_fly_screen不作为新开关授权。有需要飞屏的车型手动开启，下次连接生效。

关闭时取消尚未完成的高德准备/返回流程及自动全屏恢复队列。不改高德本身设置，不强停它。仪表全屏格式、内容选择和手动操作仍沿用既有实现；HUD开关独立。

状态及原厂高德处理保留在customizations/changan-projection。上游通用层通过VehicleCustomizations的可选自动投屏设置接口读写，不引入高德包名或车辆协议。设置页面修改后刷新关联开关。集成检查覆盖这几个入口，防止以后合并上游时只剩设置而没有执行路径。

## 重新吸收公版修复

公版来源为shihabal3amri/DiPlay v0.2.22 / 28d6002ba00320f0ba745212160b08759e4f60b9，11月5日核对仍是最新公开发行。它与Gitee长安上游的版本线不同。

60、61旧试验包已作废。检查确认它们的吸收提交不是71祖先，相关关键入口也未进入71；不能当成已启用。本次重新选择性移植860b8ac、d1af995、96690f9、d20d6bc、d0f09b2的修复，解决当前源码冲突，不沿用旧包验证结论。

- 触摸移动队列合并，多点手指身份/坐标修正，保留三指飞屏与四指设置拦截。
- 协议TRACE按需生成，避免不保存日志时仍分配大十六进制字符串；保持现有精简日志预算。
- mDNS避免反向域名查询；Activity重建接管正在运行的会话。
- 软件Opus断言异常恢复；RTSP、iAP、Bonjour、plist、USB NCM输入边界及USB授权结果保护。
- 音乐时钟采用时间平均、起播目标测量和阻塞写入到达量，保留旧容量保护，不对导航/通话调速。
- 麦克风无下行启动、有限重启、采样时钟与MTU分包，音频线程优先级；结束自身通话时撤销自己的模式持有。
- HEVC无可用解码器时回退H.264，保留已有编码选择。
- 额外排除MTK移动数据接口被误当热点，补USB短格式标识脱敏。

与71冲突的Host/Controller位置保留mainAudio资源确认及手机音频状态回调，没有回退到60的旧资源状态字段。changan-audio、changan-hud、changan-media模块及媒体按键类保持71源码；71断连解码修复保留。

新增一个应用自身signature级USB结果保护权限，不新增危险权限或用户授权弹窗。既有两个未选入的测试失败保留，不宣称全仓库绿灯。

## 用户确认的可选功能

均默认关闭、下次连接生效。

1. 接收车道引导数据：iAP2声明0x5204与最多8条车道容量，采用公版结构化解析，变化去重后写精简诊断。不开启时不增加该能力声明；不新增车道绘制，不改变本车HUD发送链路。公版样例来自作者车辆，不等于本车或手机高德已确认发送。
2. 导航语音高采样率：公版#622方案，排除8/16kHz PCM，不改变音乐、通话或音道路由；不宣称音量提升。
3. 通话原生采样率：公版#898方案，通话输入/输出共同协商8/16/24/32kHz单声道PCM，由手机选择；不强制所有声音走低采样率。

车道来源#1028。没有加入设置备份、手机网页下载日志、自动升级、比亚迪/领克专用服务或旧氛围灯接口。
