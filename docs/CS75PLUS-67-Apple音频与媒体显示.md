# 67：CarPlay音频交接与原车媒体显示

版本`0.2.22-ca75plus.25-media.3`，内部版本67，基于64→新65→新66的功能支线。公开资料可核对的接收端规则按下表实现；这不是MFi认证声明，公开WWDC资料不能替代完整MFi协议和硬件验收。

## 官方规则与对应实现

| 公开依据 | 实现与本次改动 | 边界 |
|---|---|---|
| 无线认证完成、Wi-Fi内iAP2就绪且收到disableBluetooth后，断开与目标手机的蓝牙连接 | 保留同一会话的三项交接证明，处理目标A2DP/HFP/PBAP/PAN，观察AVRCP；增加目标ACL未连接的完成条件 | 逐设备请求返回true不作为成功；未知状态、其他角色未结束或ACL接口不可用均不报完整交接 |
| mainAudio与mainScreen独立；以modesChanged确认资源归属 | 保留已有mainAudio解析；媒体扩展新增sourceSelected，确认PHONE拥有主音频且本地媒体租约仍有效才发布原车卡；原车拥有音频或永久失焦时暂停态也不抢卡 | 短暂失焦保留租约；当前协议缺失/非法状态不会被当作确认选中，不靠播放元数据抢焦点 |
| Alternate audio用于提示、导航，不与mainAudio同样争用 | 保留原有导航/媒体分流、提示混音与手机协商采样率 | 车机的媒体12、导航10是本车配置，Apple文档没有规定这些编号 |
| 车内媒体按钮控制CarPlay媒体播放 | 保留已有HID按下/释放、窗口与MediaSession去重、连接代际校验；不追加自动PLAY | 用户明确关闭按键接管只交回原车按键，不再取消无线音频交接或开启蓝牙音频混合路线 |
| 资源临时借用后按系统状态归还 | 保留现有通话/Siri音轨与模式恢复；短暂Android失焦不再当作原车媒体显示源变化 | 微信/其他手机App是否续播仍由实际手机状态驱动，不猜测并强制播放 |
| 断链重连不能沿用旧会话请求 | 保留交接gate、媒体命令及扩展owner隔离；新显示会话使用新的本地显示令牌 | Wi-Fi断链与手动断开分别验证，不以一次成功覆盖所有断链情形 |

来源：[WWDC17 Wireless CarPlay](https://developer.apple.com/videos/play/wwdc2017/717/)、[WWDC16 Part1](https://developer.apple.com/videos/play/wwdc2016/722/)、[WWDC16 Part2](https://developer.apple.com/videos/play/wwdc2016/723/)。上表是规则概述及实现对应，不包含新的私有协议字段。2.4GHz共存、其他蓝牙角色或OEM权限仍需平台能力支持，本次不改热点频段或整车蓝牙开关。

## 目标蓝牙交接与通话保护

`AndroidTargetBluetoothLink`只处理当前已认证手机地址，不取消配对、不改连接优先级、不操作其他手机。A2DP/HFP/PBAP/PAN使用既有逐设备接口，AVRCP只观察。无代理时，适配器报告该角色全局未连接才能判目标也未连接，避免未启用的PAN一直被标为未知；全局有连接不能推出目标状态。

完成条件包括各角色已断开和`BluetoothDevice.isConnected()`确认目标ACL未连接。接口被拒或未结束的其他角色仍使交接保持未确认，不用“支持的角色都断了”冒充全部断开。读取ACL方法缓存，每会话只记录一次不可用错误。

每次请求前保留AudioManager通话模式保护，以及可用时的HFP通话列表检查。Java层getCurrentCalls不可见时，新增Android9专用的`AndroidHfpCallState`：

- 绑定本车原厂导出的`HeadsetClientService`，以本App UID调用，保留服务端权限检查，无新增权限。
- 仅查询同一设备的连接状态和当前通话数量，不解析、记录电话号码，不发送呼叫控制命令。
- Android9 ABI的查询编号5、10已对照API28框架Stub并加入运行时单测；其他Android版本不使用该ABI。
- 先要求该端点确认目标HFP已连接，再将空通话列表解释为无通话，防止服务不可用时返回空列表造成误判。权限失败、空绑定、未知/异常结果都不能放行。
- 通话广播仅触发重新查询已选目标；不采用其他设备事件中的状态。连接结束时释放服务和监听。

本地原厂蓝牙APK SHA256为`614d335dae7052b005acb605790116c01508cb92ef379a0717ee3a036dc31311`。清单、查询方法体和既有逐设备断开权限证据已归档。本次不修改隐藏API策略，普通接口拒绝后不使用全局断开代替。

已有媒体流也不能证明交接结束。显式播放及正在播放时的NEXT/PREV均先核对当前交接，再发送一次原指令；已完成时立即继续，未完成时有期限地等待。暂停不等待，且取消旧准备请求。该顺序反例单独在修复前复现1项失败后修正，防止下一首先发、蓝牙稍后断开又影响播放的竞态。

## 原车媒体显示

显示对象使用当前手机连接内稳定的本地sourceID。歌名、歌词、歌手/专辑分批更新不再重建显示对象；不把本地令牌冒充手机歌曲ID。新手机会话分配新的正数令牌，旧owner不能发布到新连接。

`sourceSelected`与短暂焦点中断分开：原车主音频接管时停止本模块上报，保留待恢复数据；暂停仍发送真实暂停元数据、保留封面、停止进度；CarPlay连接结束后停止发送并释放绑定。封面只在新有效图片、原厂要求的暂停刷新、确认显示源恢复或服务重建时发送。相同内容缓存继续复用，保留1.5MiB预算与读取宽限。

真实20:11字段交换样本、瞬时焦点抖动、暂停时原车接管、ACL未知、只读权限拒绝等已纳入回归。此前“新歌必须换显示ID”的测试改为“同一显示会话令牌稳定且新文字、封面、进度继续更新”；旧媒体单次发送、旧会话阻断、暂停与文件安全断言继续保留。原media-only测试强化为未知通话状态下不放行任何角色，并验证已确认空通话后才能处理目标全部角色。

进度另修正重复0毫秒样本：解析器只为明确携带且有效的elapsed字段增加本地样本序号，标题更新不增加。Android播放状态和仪表进度据此重建锚点；样本序号不参与媒体元数据变化比较，避免位置更新反复转发封面。它不改变iAP2字段或增加协议请求。
