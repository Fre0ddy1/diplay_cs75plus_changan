本候选版从64提交 `7bab7218fe1f0497aafe1806c3f9d5a95a0f0127` 直接开发，版本为 `0.2.22-ca75plus.23-media.1`、内部版本65。此前65的投屏入场拦截和66的注入试验均作废；历史文件保留，代码没有纳入本分支。本版尚未安装或实车验收，不是发行版。

## 已实现的链路

```text
iPhone QQ音乐等CarPlay当前媒体信息/封面
  → DiPlay已有的CarPlayNowPlaying、封面解码缓存
  → CarPlayMediaKeys只读通知 → 通用媒体快照适配器
  → 独立changan-media模块的单一后台发布队列
  → com.incall.interactive / DoubleInteractiveService
  → 原车仪表媒体信息显示链路
```

模块只发送本车已分析的三个显示事务：

| 事务 | 内容 | 规则 |
|---|---|---|
| TX37 | `playStatus`、`programName`、`singerName`、`songName`、`sourceID`、`sourceType` | 专辑/歌手/歌名来自真实手机信息；播放=2、暂停=1、来源=25 |
| TX38 | 同一sourceID、当前位置ms、总时长ms | 仅播放时、且有有效真实时长/位置才发送 |
| TX39 | 同一sourceID、封面文件名、绝对路径 | 封面变化或暂停转换时单次发送，避免每秒传图 |

播放时约每秒发送状态和有效进度，依据已有爱趣听运行日志及独立0.4探针的60秒显示实验。播放态只有当前CarPlay媒体持有输出时才发布，避免已切换音源后继续争抢显示。暂停态不要求继续占有音频输出。

`sourceID`沿用原厂“同来源/歌名/歌手/专辑复用ID；变化后100000＋曲目索引＋0到999随机值”的规则。手机没有爱趣听SDK的索引，使用本会话本地索引；它不是QQ音乐原始歌曲ID。`sourceType=25`是Incall显示协议的值，不等于MediaCore的爱趣听Provider编号1，也不选择爱趣听作为音源。

## 暂停行为：按证据实现

本次静态核对的原厂核心APK SHA256为 `3dc00caf958198125ce6db97b1f083c81969b150305fb4c4b97a6dc231d264bc`：

- `CarflowDualManager.AnonymousClass13.onPause()`：设置状态2，使用保留的媒体信息调用`setMediaInfo`，没有清卡或断开。
- `WtCarDualInteractiveServiceIncallSDK.handleSetMediaStatus()`：将该暂停状态转换成Incall的`playStatus=1`；清除旧封面路径标记，使封面可再发送一次。
- `handleSetMediaPlayTime()`：只有输出播放状态2才发送TX38，暂停不发进度。
- `onStop()`在已检查方法中仅记录日志，不能据此补造一个通用清卡规则。

因此新版65在暂停事件发送暂停元数据，保留自己的会话绑定和封面缓存，不主动发清卡；暂停后不持续发送进度，也不假定必须每秒重发暂停状态。恢复播放后重新周期发布。手机明确清空元数据时不虚构上一首的暂停数据。CarPlay断开/退出时取消该会话任务、释放本模块绑定，停止旧数据发送。

**尚无原厂爱趣听“播放→暂停”的干净实车日志，也没有新版65暂停卡片的目视结果。** 是否需要额外刷新、接收端多久保留卡片，留待实车验证。本说明取代早期方案中“暂停也必须每秒心跳”的推测。

## 性能与生命周期

- 最多一个待处理快照、一个待编码封面、一个排队唤醒；过期会话任务作废。
- 新增Binder与文件处理在后台进行；复用已有最大384像素解码结果，输出320×320 JPEG。
- 缓存最多6个小封面，单个不超过256KiB；为原车异步读取保留至少60秒，不强删刚发送的图片。满额时延后处理新封面。
- 每个手机会话最多尝试绑定三次；断开取消本模块任务与绑定，不修改原车应用。
- 日志只记连接、曲目/状态变化、封面结果、错误和周期汇总，沿用已有有界日志存储。

## 独立封面色通道诊断包

`dev.freddyq.covercolorprobe`只验证普通应用是否能经原厂VirtualCar客户端读取/写入**当前颜色**，并不实现自动封面换色。启动不连接、不写入；用户点击连接后校验本车型号与原厂场景APK哈希，原色读取成功才开放按钮。只允许色号4、48及本次读到的原色，属性固定为`0x314003a6`、area0；回读记录0/500/2000ms结果。退出不自动写入，恢复须手动点击。

它以自己的UID调用原车SDK，不注入原车进程、不授予或绕过权限，不写灯光模式/保存设置/节点掩码/律动/音量。API返回成功或回读相同不代表实体颜色已改变，也不能证明不会被原车场景覆盖。仅面向本车Android9的诊断包target28会保留Google Play目标版本警告；主DiPlay目标版本不因此改变。

原厂MediaCore尚无已确认的通用外部发布入口；CarPlay Provider12也被已检查的灯光分支过滤。本版不能宣称“发送媒体卡数据即可打通封面换色”。待颜色权限和保持行为实测后，再决定是否加入封面Palette及原车色表映射。
