# 65候选：投屏入场与全屏重申拆分

65=`0.2.22-ca75plus.23`，基于64的`7bab721`。修正64中每次全屏重申都重复发送滑动入场事件的行为，保留已有来源接管、视频就绪确认及有界恢复。

## 问题与证据边界

64实车冷启动和暖重连都能自动全屏显示CarPlay，但用户仍看到短暂小屏。冷启动日志没有DiPlay的`setMode(1)`，却有11条`setMode(3)`；旧实现每次都发送tx21滑动事件、tx8布局ACK和tx1完成通知。与此同时，原车Tinnove回调仍收到小屏请求并自动回复ACK1。

因此，“不发送小屏ACK”不等于“没有小屏过渡”。重复滑动是否就是小屏请求的原因尚未做对照，65先消除这个已确认的重复动作，不宣称原车必经小屏，也不宣称本包已经完全消除小屏闪现。

## 实现

生产改动集中于现有唯一原车Binder入口`common/.../InCallClusterBridge.kt`，继续由`changan-projection`模块通过已有`initialProjectionLayout`契约选择自动全屏策略；不新增设置、连接或车厂协议编号。

| 场景 | 65行为 |
| --- | --- |
| 自动全屏的首次完整打开 | 没有存活通道证据且尚未派发入场时，允许一次tx21；随后ACK3和完成通知 |
| 已报告正在投屏的存活通道 | 复用通道；来源接管照常执行，不重新发送入场 |
| 保持、布局恢复、静默重申 | 仅布局ACK和完成通知，不重复tx21 |
| 当前视频窗口替换、视频就绪后的来源接管 | 保留源状态及tx2来源确认，同一存活通道不再入场 |
| 布局ACK失败 | 可继续恢复ACK；已派发的滑动不因此重复 |
| 入场事务失败 | 不记为已派发入场；后续完整激活仍可尝试，布局重申本身不冒充入场成功 |
| 通道关闭0、主动归还、掉电失效、服务断连 | 清除入场记录，后续完整激活可重新入场 |
| 新鲜确认超时，进入原有有界兜底 | 清除当前入场记录；新完整激活可再次入场，过期控制器不能清除新状态 |
| 自动全屏关闭、未加载本车定制 | 保留原有滑动与小屏/全屏序列 |

入场记录绑定当前Binder，并在明确失效边界清除；不会因换视频窗口或普通代次递增就清除。它不持久化到车机设置。入场事务派发成功只表示Binder调用完成，不证明仪表已接受或切换；实体成功仍依赖后续新鲜回调。`setMode`日志增加`entry=dispatched/omitted/failed`，移除旧启动日志中无条件写出的`C0(1)`标题，避免把固定文字当作真实小屏调用。

全屏成功条件保持不变：当前控制器/窗口代次有效，且收到本轮新的布局3与通道3确认。Binder派发成功和保留的旧状态都不作为画面已恢复的证明。原有三次有界布局恢复、视频来源接管及激活预算没有扩大。

## 文件

- `common/.../InCallClusterBridge.kt`：入场记录、失效边界、初次入场许可、布局ACK与滑动事件拆分。
- `common/.../InCallContentHandoffTest.kt`：新增10项事务/生命周期回归，并加强原有冷启动、保留通道、原厂来源接管及兼容路径断言。
- `common/.../InCallReconnectLifecycleTest.kt`：隔离新增通道状态，避免测试之间串状态。
- `common/.../GlassUiRenderTest.kt`：预览版本更新，圆角与对比度断言保留。
- `mobile/build.gradle.kts`：候选版本65。

HUD、音频生产代码、热点预填、圆角UI和卡片默认值沿用64；未合入暂停验证的61吸收支线。
