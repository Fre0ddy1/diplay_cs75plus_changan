# 原厂巡航覆盖补偿

本车日志已观察到手机有效左转输出与原厂广播期间的零图标/零距离输出交替。两者进入同一 interactive 接收通道，普通 DiPlay 应用不能阻止另一个应用的广播。

旧维护线版本42增加的补偿在新版43继续保留：长安HUD模块独立开关“原厂巡航覆盖后恢复HUD”，默认开启。仅监听全局标准广播中明确的10001零图标/零距离，或10019导航结束状态9/12。20ms合并后重新读取当前手机路线；只有正在输出、路线有效且HUD开启时，补发开始和指引。不复制外来数据，不停止原厂应用，不改巡航设置，不调用未经验证的退出巡航命令。

补偿限每250ms一次；结束导航、关闭输出、断开或投屏握手静默期间不恢复。会话结束注销监听，旧任务有代际保护；自身定向广播显式排除，防止回环。日志不猜测 Android9 无法提供的发送 UID。

**这是覆盖后的补偿，不是接收端排他仲裁。** 针对已捕获的零值/退出覆盖，不能保证任意频率和其他应用数据都没有目视闪烁，效果待实车验证，开关可关闭。真正阻止原厂输出仍需确认其设置/控制协议；未确认的 nativeSetNaviType 参数没有加入代码。

回归覆盖完整零值筛选、有效数据不触发、投屏状态不干预、突发合并、限流、自身广播不回环、无路线/断开不复活及旧任务取消。实车需分别记录巡航开关、手机更换目的地和主动退出。

## 2026-10-26实车结果

旧维护线42在S311_MCA上进入原厂巡航后仍反复闪烁；接收端有0-0与有效指引交替，模块确实进行了恢复。关闭原厂自动进入巡航并退出当前巡航后，用户报告恢复稳定，短窗口未再观察到清零。现有补偿未解决来源竞争。新版43/44沿用同一模块，不能宣称已解决；当前使用条件是原厂自动巡航关闭、原厂进程保留后台。未加入未经确认的原厂控制命令。
