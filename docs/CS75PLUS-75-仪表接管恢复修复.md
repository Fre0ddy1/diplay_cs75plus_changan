# 75版：仪表接管恢复修复

基线：74 / `377d0e5`。候选版本：`0.2.22-ca75plus.33`，内部版本75。

## 问题与修复行为

实车出现CarPlay主屏和HUD正常、重连后的仪表停留在原厂地图，手动滑屏也未恢复。保存日志显示视频首帧已到达，源切换IPC成功，但新一轮全屏布局与通道状态没有完成确认。

内容接管策略原先把“请求已发出”保存在窗口去重标记中。确认超时后仅使全屏状态失效，没有使内容发送标记失效，因此同一窗口的后续首帧通知不能再发起接管。现在超时会通知内容策略，释放该窗口的发送标记，继续使用原预算内剩余的一次接管机会。

手动滑屏原先统一暂停自动内容恢复。现在先区分当前窗口是否已完成源切换和本轮协议确认：已确认窗口继续静默切换；尚未确认时，明确开屏操作会恢复当前窗口的内容接管。明确关屏仍停止恢复。自动选项关闭时，也只有明确手动开屏才允许这条恢复路径，不会顺带开启设置。

回调注册还修正了一个返回值问题：原先忽略原车返回Parcel中的异常，只根据Binder事务返回值标为注册成功；现在远端异常会返回失败。

## 有界与生命周期约束

- 当前窗口的内容接管预算仍为最多2次；首帧轮询与确认超时不会补充预算。
- 每轮全屏确认仍最多3次，沿用既有协议和时序。
- 显式手动开屏可开始一个新预算；正常已确认的画面切换不重新抢占来源。
- 旧窗口的失败通知、延迟发送结果及旧控制器不能取消或确认新窗口。
- 会话结束、窗口销毁和用户关闭仍取消待执行动作。
- 不新增设置、权限、后台定时器或原车注入方式。
