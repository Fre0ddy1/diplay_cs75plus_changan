# 长安仪表重连恢复（45）

44版在S311_MCA实车上出现：主动断开后重新连接，CarPlay主屏、手机导航和HUD正常，仪表没有恢复。应用已经收到111地图流，自动飞屏也已执行；旧Activity销毁、新Activity创建，但进程内桥接仍记为开启。收到视频不能作为物理仪表恢复的证明。

## 本次修复

- 服务绑定统一由Application Context持有。重复观察复查连接与回调注册；不重复绑定正在连接的服务。Binding死亡和空绑定释放旧注册，断开时清理旧回调缓存。
- 仪表窗口使用独立的弱引用标识。新窗口复用旧通道时，显式恢复定制策略；同一窗口的手机重连只重新挂接策略，保留仍在进行的源切换握手。
- 新窗口暖恢复先等待1500ms，再沿用既有FULLSCREEN控制端点，最多3次、每次等待2500ms。该路径不先切小屏。
- 暖恢复的确认要求在本次请求之后收到新的全屏布局和通道开启回复；即使值仍是3，也计入新回复序号。旧缓存和请求返回值均不能代替确认。
- 超出暖恢复预算才使旧确认缓存失效，交回上游已有的有限通道激活逻辑。新页面、会话结束和手动接管通过周期标识拒绝旧控制和迟到回复。
- 关闭自动全屏时不接管暖恢复。HUD发送和原生转向卡视频保持原有链路。

通用生命周期契约在`customizations/api`，重试策略在`customizations/changan-projection`；既有`InCallClusterBridge`继续独占车辆Binder和协议处理。Host只保留窗口观察、恢复和结束通知。集成检查覆盖这些入口，便于合并上游时发现遗漏。

## 验证边界

本地回归覆盖新窗口、同窗口重连、重复通知、同值回复及顺序交换、过期控制、结束/手动取消、服务绑定与死亡、关闭设置和有限预算。签名APK仍需在驻车、ADB关闭及原厂高德后台条件下验收；离线模拟不能证明实体仪表已恢复。

原厂自动巡航造成的HUD竞争未在此修复；继续保留关闭自动巡航的使用条件。不修改原车转向卡显示。

## 45版后续实车记录（2026-10-26）

上述为修复设计及构建时的验收边界。随后45版已在S311安装：用户确认HUD右转／距离／路名一致，观察约60秒未闪烁；关闭ADB后重新连接可自动全屏，内容选择正常。一次日志从会话active到仪表窗口确认约2.861秒。

较早会话同时存在约47.9秒后确认以及结束时未确认的记录，其精确ADB开关时间不完整。用户最后确认目前连接会自动全屏、此前可能ADB未关；不能把该猜测当成确定根因，也不将单次成功扩为每次重连都即时稳定。46发行版沿用此逻辑，仅更新名称、元数据与说明。
