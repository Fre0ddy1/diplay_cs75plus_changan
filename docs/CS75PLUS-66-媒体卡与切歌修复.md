# 新66：媒体卡与切歌修复候选

日期：2026-11-01。版本`0.2.22-ca75plus.24-media.2`，内部版本66；由新65（`850e5be`）继续迭代，投屏沿用64。与已作废的旧65、旧66内存接入实验无关。

## 实车证据与修复范围

新65实车未通过媒体卡验收：同一首歌封面闪烁，暂停后切下一首再播放时封面、进度丢失。手机QQ音乐通过CarPlay播放；用户确认标题像歌词变化。日志中16:59以后有71次曲目ID变化，仅有11条媒体按键事件。另有原车蓝牙source20和DiPlay source25并行输出，不能将接收成功等同于仪表稳定显示。

方向盘切歌偶发暂停也在前一晚出现，不能归因于新65新增媒体卡。今天16:47的一次NEXT只记录到DiPlay发送一次，随后手机状态变成暂停。蓝牙交接日志还显示ROM缺少HFP的`getCurrentCalls`方法，导致原实现连A2DP都没进入断开步骤，PAN未知状态又阻碍成功判定。这些是可定位的缺陷与竞争条件；尚不能证明已经排除了手机音乐应用本身的暂停原因。

本版修复：

1. **动态标题与曲目身份分开。** 通用快照增加可选`sourceApp`。仅对实测的QQ音乐、且artist/album均非空的情况，用这两个稳定文本关联仪表显示ID；歌词标题仍按手机实际数据发送，不猜测并替换手机字段。其他应用继续用完整文本键。它不是手机持久歌曲ID；同歌手/同专辑下若稳定字段相同，两首歌可共用显示ID，文字、进度和封面仍更新，需要实车检查。
2. **封面按当前手机会话的传输ID关联。** 回调到达时仍检查当前曲目，拒绝过期图片；一旦合法接收，允许图片先于完整文字到达。相同借用Bitmap不重复复制，异步只处理模块自己复制的图片。暂停事件按原厂路径刷新封面一次，正常继续不重复刷图；持续播放中丢失并重获输出归属时补一次显示。
3. **缓存按字节预算限额。** 复用相同内容的JPEG优先于容量判断。保留原有1.5MiB图片预算，改为最多128个文件、单图256KiB，允许多张实际只有数KiB的小图；另有一份最多256KiB临时编码文件。仍保留60秒读取宽限，不为新图删除原车可能正在读取的新文件。
4. **进度不被歌词更新反复拉回。** 仅实际elapsed值变化才重建锚点，标题刷新继续用单调时钟；暂停冻结、恢复不累计暂停时长。
5. **媒体交接只处理目标手机A2DP。** 只断开媒体角色11，观察11/12；不再等待电话簿/PAN断开，也不请求断开电话角色。保留AudioManager通话门控及可用时的HFP通话列表检查；仅缺少该可选方法时允许媒体处理。隐藏API拒绝仍记录失败，不绕过权限。AVRCP是否随A2DP断开有待本车确认。
6. **切歌不在未解决的焦点竞争里重抢。** NEXT/PREV遇到短暂丢失焦点时，先做有期限的媒体交接检查；检查失败不再抢焦点，仍只发送一次原按键，不自动追加PLAY。显式播放恢复及旧会话取消规则保留。

## 链路与文件

手机QQ音乐 → 现有CarPlay媒体解析/封面队列 → `CarPlayMediaKeys` / `PhoneMediaSnapshotAdapter` → 通用扩展契约 → `changan-media` → 原厂`DoubleInteractiveService` → TX37元数据、TX38播放进度、TX39封面文件 → 原车仪表。

| 文件 | 作用 |
|---|---|
| `customizations/api/.../MediaCustomization.kt` | 增加通用可选媒体来源字段，不放原车协议编号 |
| `common/.../PhoneMediaSnapshotAdapter.kt` | 来源透传、连续进度锚点 |
| `common/.../CarPlayMediaKeys.kt` | 封面来源透传、按键准备结果与焦点恢复顺序 |
| `customizations/changan-media/.../IncallMediaProtocol.kt` | QQ显示身份、会话内封面键；TX及字段不变 |
| `customizations/changan-media/.../ChanganMediaCustomization.kt` | 当前封面校验、去重、输出恢复与暂停/继续时序 |
| `customizations/changan-media/.../MediaCoverCache.kt` | 相同图片复用及有界字节预算 |
| `customizations/changan-audio/.../AndroidTargetBluetoothLink.kt` | 仅媒体交接，缺少可选HFP方法的处理 |
| 对应模块及common测试 | 新缺陷回归，同时保留旧断言 |
| `mobile/build.gradle.kts`、版本预览测试 | 新66版本标识 |

投屏桥、HUD、音轨Sink和原有封面解析队列不在本次修改范围。仪表仍走64的已验证入口；没有内存注入、伪造仪表请求、音源切换指令、自动补播放或新增音轨。
