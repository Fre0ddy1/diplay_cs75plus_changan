# CS75PLUS 59版：窗口刷新与来源交接后的确认

2026-10-30。文档经由Codex（GPT-6.1 Sol）编写。

58版实测中，高德初始化成功，但首次全屏显示原厂地图；暖重连一次不全屏，第二次才出现CarPlay。两类问题分别处理，HUD和音频行为保持原方案。

## 窗口更新

高德的仪表Presentation是在DiPlay窗口之后创建的。前置返回时，只回到Host不足以更新已有仪表窗口。59版返回同一个Host后，释放DiPlay自身旧窗口/Surface并新建隐藏窗口，等待新窗口视频帧后再交接来源。没有操作原厂窗口、抬高全局窗口层级、替换手机连接或启动第二条导航。

窗口Surface回调增加当前窗口身份检查，旧窗口迟到的销毁/创建回调不能覆盖新窗口的输出绑定。窗口在show之前登记当前身份，使同步到达的首个Surface回调也能生效。

## 交接后的新确认

来源交接会替换vendor调用代次。58版重置模块后只等待新的布局回调，导致正在进行的全屏重试丢失，旧代次的控制端也不能继续工作。

59版在来源交接时为当前窗口重新绑定控制端，并明确启动一轮有次数上限的新确认。保留请求前的callback serial边界，只有请求之后收到的全屏和通道两类回调才确认；旧缓存值或Binder发送成功不代表确认。旧窗口或旧会话的控制端不能请求布局或撤销新窗口确认。

链路为：前置返回 → 新窗口出帧 → 来源交接 → 当前代次全屏/通道确认。每轮仍至多3次全屏请求，内容交接仍有限次，手动关闭/退出、掉电和会话结束的保护保留。

## 为什么仍保留短暂打开高德

2秒是StockAmapBootstrap的保守等待值，不是Android或高德规定。仅启动进程与执行Activity初始化不同；Android也区分Activity生命周期与服务。今天冷启动时高德主进程及Ehp/JsonProtocol后台服务已经由系统启动，仍未完成本车所需的仪表前置。当前证据不支持用startService或“进程存在”替代地图初始化。

未来可继续寻找可公开调用的初始化接口或可靠就绪事件，再缩短等待/静默初始化；当前没有验证这样的入口。本版不假设“必须精确前台2秒”，也不把等待改成更短数值或用覆盖/隐藏原厂界面伪装静默。正常、已准备好的暖重连会复用模块准备状态，无需每次都弹高德。

参考：[Android Activity生命周期](https://developer.android.com/guide/components/activities/activity-lifecycle)、[前台服务说明](https://developer.android.com/develop/background-work/services/fgs)。前台服务不等于把地图Activity切到屏幕前面。
