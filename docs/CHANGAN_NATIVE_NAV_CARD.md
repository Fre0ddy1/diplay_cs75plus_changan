# 原车转向卡与HUD的公共导航输入

用户在S311_MCA仪表速度表上方看到原车转向卡，外观与原厂高德投屏时相同，加入长安HUD功能后出现。本次要求只查来源，暂不隐藏。

## 当前链路

手机iAP2导航数据经适配器进入`changan-hud`，模块发送`AUTONAVI_STANDARD_BROADCAST_SEND`到`com.incall.interactive`：开始/结束使用10019，箭头、距离和路名使用10001。

本车原始interactive APK的静态代码显示：

1. `GDBroadNavigateClient.onReceive`处理10001，将`NEW_ICON`转换为原车转向编号，分别调用`roadName`与`navigateTurnInfo`；10019进入`navigateStatus`。
2. `DoubleNavigateManager`将数据交给统一传输接口。`DataTransferWrapper.sendNavigateTurnInfo`会遍历已注册的传输实现转发，而不是根据发送应用名称选择某一个显示屏。
3. `CanDataTransfer.sendNavigateTurnInfo`写入两组原车导航属性，包括557855796/557855797和557842584/557842585/557842586。标准接收入口没有提供本模块使用的“仅HUD”显示标记。
4. 本轮只读日志同时观察到标准广播接收、Manager转向输出与CAN导航属性更新；IPSocket支路也有日志。部分系统状态广播来自后台原厂高德，不能仅凭这些广播认定原厂也在路线导航或巡航。

因此，HUD适配接入的是原车公共导航输入。结合用户目视，原车卡片随这一路导航源共同出现符合现有证据。最终绘制仍由原车侧控制；未把上述每个属性强行标为某一块屏专用，也未完成隔离输入的物理显示实验。

## 三种卡片的区别

| 内容 | 来源与控制 |
|---|---|
| 速度表上方原车转向卡 | 原车公共导航数据，由原车仪表绘制 |
| “Apple完整导航”的转向视频卡 | 手机提供的独立指令卡视频流 |
| DiPlay自绘导航卡片组 | DiPlay按仪表内容选择绘制 |

“仅地图（不显示DiPlay导航卡片）”入口在0.2.22定制移植提交`a39af82`加入，43/44已有；该选项恢复了MAP保存值的可选入口，让本地导航卡片组能明确关闭。它不控制原车转向卡、HUD或独立歌曲卡的开关。

本次不删除导航属性或发送未知关闭命令。以后如需单独隐藏原车卡，须先验证独立显示控制，避免影响HUD及其结束清除。
