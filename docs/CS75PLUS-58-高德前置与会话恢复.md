# 58候选：原厂高德前置与当前会话恢复

版本：`0.2.22-ca75plus.16`（58）。基于57支线，未合并或改写master。文档经由Codex编写。

## 问题与行为

S311_MCA实车对照中，Android重启后高德后台服务会自行启动，但未打开原厂地图界面时，首次连接及单独重连CarPlay均不能投屏。只打开高德再返回，旧连接也没有恢复；打开高德后重建CarPlay会话才收到全屏确认。

因此不恢复旧版“有进程就跳过”的判断，也不重加常驻进程扫描。58在本车模块中补齐地图初始化前置，然后重新允许当前连接的激活和视频内容交接，目标是免去用户手动打开高德、断开重连的步骤。具体底层依赖尚未完全证明，58仍需实车验收。

## 链路

`手机会话有效 + 显示器已上电/尺寸就绪 + InCall已绑定 → 检查实际通道确认 → 必要时打开原厂高德地图入口 → 约2秒后返回同一DiPlay Host → 重置有界激活预算与当前窗口内容交接 → 重新等待车端确认`

- 包名、启动策略、等待时长和缓存只在`changan-projection/StockAmapBootstrap`中。
- 通用API新增`ProjectionActivationControl.launchPrerequisite(Intent)`和`returnToProjection()`；Host只负责生命周期与会话归属检查，不含高德包名或进程探测。
- 返回使用现有Host，不重建手机连接。恢复激活仍走既有InCall桥；内容交接仍以本地视频帧为前提。
- 高德界面返回不等于已完成真实投屏：后续仍需InCall全屏确认和物理画面验收。

## 预算、取消与暖启动

已确认健康通道的同服务代次不会重复打开高德。若此前准备过的代次后来不再确认投屏，原有有界激活耗尽后，每个会话只允许一次地图前置补救；不无限拉起、不无限重发。

前置进行期间暂停模块的自动激活/内容交接。前置返回后清除旧的恢复预算及内容交接完成标记，允许同一个视频窗口重新发起真实源握手。

断连、用户关闭投屏、手动接管、显示器掉电、服务代次变化或应用退出会取消不适用的延迟返回。Host在启动与返回时再次确认当前会话、自动/手动请求、显示器和退出状态，旧回调不能启动新会话或绕过“保持退出”。

地图启动失败或原厂包缺失时，记录一次原因，保留原有有界直接恢复路径。没有启动原厂路线导航、修改巡航设置、强停高德或操作系统服务。原厂高德自动巡航仍应按发行说明关闭，避免HUD竞争。
